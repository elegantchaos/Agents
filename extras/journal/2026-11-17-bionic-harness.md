## Evidence And Limits

The installed Bionic version is 1.2.1+10. Inspection of its bundled code confirms a repository `AGENTS.md` loader that walks from the working directory to the nearest Git root, and a user skill directory rooted at `~/.lmstudio/skills`. Its initial skill preferences had no other-app directories enabled. The custom reviewer preference field only affects shell-command review, so it is unsuitable for personal chat instructions. No supported user-global startup instruction hook was established; the explicit session invocation is required for the personal voice.

[Bionic's skill documentation](https://lmstudio.ai/docs/bionic/agent/skills) describes standard Agent Skills, explicit `@` invocation and discovery from other apps. This shares plugin skill content; it does not establish compatibility with marketplace installation, hooks, connector tools or runtime approvals. [LM Studio's Codex](https://lmstudio.ai/docs/integrations/codex) and [Claude Code](https://lmstudio.ai/docs/integrations/claude-code) integrations expose Responses and Messages APIs respectively. [llmster](https://lmstudio.ai/docs/developer/core/headless) provides headless serving but has not been installed or configured separately here. PiSwift and PiSwiftTui were inspected through their READMEs, not built or evaluated.

## Validation

The parent checkout was clean and matched `origin/main` after fetching. Mint confirmed AgentTools 4.1.0 and ReleaseTools 6.0.0 were current. `agt skills status` reports the three standalone skills clean at their recorded revisions, with existing Claude and Codex links intact. A broad refresh, rule synchronization and plugin reinstall were skipped because this work does not change their sources or installed configuration.

All seventeen installed links resolve to readable `SKILL.md` files with valid names and descriptions. The new session skill passes the skill-creator validator. The manual installation snippet passes zsh syntax checking, and changed guidance uses portable home paths. Markdown links and whitespace are checked before commit. No plugin guidance changed, so no plugin version bump is required.

A bounded read-only Codex CLI 0.169.0-alpha.11.1 run against local `qwen3.5-9b` used the existing user skills and plugins, with external MCP servers disabled for the invocation. The server connection and shell tool calls succeeded. Acceptance failed: the model initially requested invalid or unnecessary escalation, read only the first fifty lines of required files, invented `agt skill list`, searched incorrect skill paths, and timed out after 180 seconds before its final response. Codex also emitted model metadata decoding warnings and a nonfatal model-load HTTP 500. This proves basic transport and tool execution, not reliable instruction compliance or coding suitability.

The same request against the already-loaded `qwen3.6-35b-a3b` completed with exit 0 in approximately 80 seconds. It read all of `VOICE.md` and `COMMON.md`, discovered the installed baseline standards and Swift language skill files, and correctly reported “Understand request boundaries.” It tried incorrect skill paths before recovering, and spoke before reading `VOICE.md`, so this is a successful transport and discovery check with a startup compliance failure. The same metadata and nonfatal load warnings occurred. Neither run proves coding quality, and the shared project instructions were injected by the harness rather than independently opened by the model.

At Sam's request, tested Claude Code 2.1.281 against the same 35B model using invocation-local Anthropic endpoint settings. The init event confirms baseline 0.8.35 and Swift 0.11.4 were enabled and their skills discovered. The run exposed Read, Glob, Grep and Skill tools, disabled hooks and external MCP servers, and made no persistent configuration changes. It returned exit 0 in 38.7 seconds but made no tool calls, claimed the local baseline was unavailable and read from GitHub despite no web tool, and quoted an AGENTS.md rule as the first COMMON.md workflow rule. Acceptance failed. These runs have different tool catalogs and are not a controlled timing comparison.

A focused retry with the same Claude configuration explicitly required a Read call on the canonical `COMMON.md`. This succeeded in 16.5 seconds with a real Read request, a successful tool result, and the correct workflow rule. The local Claude backend and file tools are functional. The broader test still fails autonomous verification acceptance; the focused success does not erase that result.

Bionic's native UI discovery and model-driven session bootstrap, and an actual code-change/test task remain unverified. No application code changed, so builds and code test suites were not run. Checklist review covers canonical ownership, personal voice isolation, runtime capability boundaries, accurate installation scope and explicit validation gaps; no decision or design documents were changed.
