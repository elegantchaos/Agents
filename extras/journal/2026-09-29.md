## Under consideration: auto modes instead of approval rules

- Sam is considering standardising on Claude Code's auto mode and Codex's auto-review, which would make the rules half of the refresh (`agt rules`, `default.rules` triage) obsolete. Codex prefix rules in particular have proved unreliable. Decision deferred.
- Research summary:
  - Both vendors say their reviewer is not a security boundary.
  - Anthropic publishes a 17% false-negative rate on real dangerous actions for auto mode, and closed a working prompt-injection RCE chain (Rehberger, 60–80% success) as out of scope.
  - Codex auto-review only reviews sandbox-boundary crossings.
  - Independent write-ups agree that the sandbox, network egress limits and credential isolation are the real controls.
- If adopted:
  - keep `agt sandbox configure`, which both modes rely on;
  - retire `agt rules` from `baseline:refresh` and `COMMON.md`;
  - Codex prefix rules bypass the sandbox without review, so removing them is a safety gain, not a loss.
- Related open question: keeping SSH keys and the `gh` token usable by agents without being readable by them.

## SwiftUI workshop review

- Compared the Palette Library workshop projects (Start vs Final, sections 2–6) with the `swift:swiftui` skill. Most lessons were already covered. Added to `data.md` and `performance.md`:
  - `@State` initialised from an input in `init` goes stale; use an optional model with `.task(id:)`;
  - no `@State` for constants;
  - no closure view inputs; use a binding;
  - no pass-through properties; use the environment;
  - store derived flags on the model rather than computing them in a fast-changing parent;
  - row closures should not read shared collections;
  - a "Diagnosing view updates" section covering `_printChanges`.
- `@State` must be `private`: a non-private property joins the memberwise initializer (checked with `swiftc`), so its default expression runs on every construction. The lazy once-only behaviour of the SDK 27 `@State` macro is documented by [Nil Coalescing](https://nilcoalescing.com/blog/InitializingObservableClassesWithTheStateMacroInXcode27/). Neither that article nor a second one says `private` is required, so the skill states the initializer mechanism rather than claiming the macro demands it.
- `_ = Self._printChanges()` does not compile inside a `ViewBuilder` body (`()` cannot conform to `View`). `let _ = Self._printChanges()` does, and is what the workshop Finals use.
