# Worktree Setup Before TDD

The baseline Git skill delegates new worktree setup to `agt worktree create <name>`. AgentTools owns the directory, branch, semantic-name and collision rules, initialises submodules and invokes dependency preparation. COMMON.md points to the command and skill instead of duplicating the location and branch conventions. Runtime integration remains in guidance: use the reported absolute path, attach an existing checkout when the runtime supports it, and retain that explicit path when Codex rejects a checkout as unmanaged. Do not create a second checkout to obtain an attachment.

The Swift validation skill runs `agt prepare` before the first red test in an existing fresh checkout. New worktrees already receive preparation during creation. Both commands require explicit approval or user execution when they must run outside the sandbox; neither command escalates itself. Guidance distinguishes dependency Git metadata denials from cache and network blockages, and distinguishes preparation from validation. All tests, including red/green steps, still use `agt validate`. Repeat preparation after dependency changes, changing to revisions needing other dependencies, removing checkouts or cleaning validation output.

Claude and Codex restrictions are not described as identical. This Codex session successfully cloned into nested `.git` directories and ran Bookish preparation inside the existing sandbox. Claude's published sandbox source contains recursive Git config/hooks protections beneath the working directory; actual Claude acceptance remains outstanding. The attempted additional restricted sandbox could not be started inside this session, and no outside-sandbox fallback was used.
