# One Worktree Per Session

Sam found Bookish's NR1 branch checked out in the main checkout. The reflog showed every task branch for days had been made there with `git checkout -b`. The git skill opened its worktree section with "reuse a suitable existing checkout or worktree", and an agent could read the main checkout as suitable. That wording was there to stop worktrees multiplying within a single session, which had been happening before. Bookish's AGENTS.md also allowed "a `feature/` branch without approval" and said nothing about a worktree, while the sandbox made `git checkout -b` free and `agt worktree create` cost an approval.

The skill now gives each session one worktree, made without asking when its first task starts; the main checkout and other sessions' worktrees never count. Later branches in the same session, for a diversion or a stacked PR, are created in that worktree after committing what is in progress. Unrelated work prompts an offer of a new branch, which came from Bookish's AGENTS.md, and that file drops its line. A second worktree needs the user's request or two branches checked out at once. The rule does not name a creation tool, so Codex's refusal to use `agt` for worktrees is still handled by the existing runtime conflict clause. Baseline plugin 0.8.38.

The first Bookish worktree for this fix branched from NR1, because `agt worktree create` without `--base` uses the invoking checkout's HEAD. That PR picked up seven NR1 commits until it was rebased. The skill now says to pass `--base origin/<default-branch>` for a session's first task. The same session then made a second Bookish worktree for the snag list, which is the multiplication the reuse rule prevents.
