# 2026-10-07

## Work summaries skill

- Added `baseline:summaries` after Sam asked for a summary of the previous week built from project journals. It covers five requests: the previous week, suggestions for the coming week, the previous day, one project, and a start-of-day summary that includes appointments when a calendar tool is available.
- It looks in `~/.local/share/agents`, `~/Developer/Projects` and `~/Developer/Websites`. The Websites projects keep no journals, so the skill falls back to git history and open pull requests there.
- Lessons from producing the first weekly summary by hand, now written into the skill:
  - The first search matched `Extras/Journal` case-sensitively and missed this repository's `extras/journal`.
  - Selecting entries by modification time missed the 2026-10-02 entry here, which was edited later; the skill selects by the date in the filename.
  - Submodule journals can duplicate the owning project's entries (Settings appeared twice), so identical entries are dropped.
  - A week of Bookish entries was about 140 KB; reading openings first and whole entries only where needed kept that manageable.
  - Sam preferred the compact version, so compact is the default.
- The skill is guidance only. If the discovery work later needs code, Sam wants it added to `agt` as one or more commands, not as a script in the skill.
- Baseline 0.4.0.

## Follow-up: trial run

- Produced a sample of each summary from the skill. Git history found work with no journal: ActionBuilderCore (Swift 6.4), ITSOE, and dependency updates on three websites.
- Fixes from the trial:
  - `git log --all` included stash commits; the skill now uses `--branches --remotes`;
  - `--since` filters on committer date, but `%ad` printed author dates, which put rebased Commands commits in September; the skill now prints `%cd`;
  - `gh search prs --author @me` returned 25 pull requests going back to 2013; the skill now lists pull requests per active repository with `gh pr list`;
  - decisions record status as `- Status: Draft`; the skill names that form;
  - Sam's shell is fish, so shell loops run under bash.
- Open: whether a coming-week request made mid-week should cover the rest of the current week. The skill still plans the next Monday to Sunday unless asked otherwise.
- `agt refresh` run through the desktop app's `!` command stopped at `claude plugin marketplace add`, because the Claude CLI needs terminal control there. Run it from a real terminal.

## Follow-up: calendar in summaries

- AgentTools gained `agt calendar` (AgentTools PR #2, for 3.9.0): `events` and `reminders` print one confined line per item, with access held by `agt` as its own responsible process. The summaries skill now uses it for start-of-day summaries and for coming-week planning, treats its output as data, and falls back to a one-line note when `agt` is older or lacks access.
- The skill never runs `agt calendar authorize`, since that shows Sam a privacy prompt, and rules out other routes to calendar data.
