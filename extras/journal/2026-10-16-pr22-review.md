## Findings

1. **Should fix: preserve omission semantics when recommending a fixed container.** `plugins/swift/skills/swiftui/references/performance.md:4`, repeated in `references/patterns.md:99,146` and `SKILL.md:59-60`, mandates a container around every conditional reusable control and toolbar, menu or list-row view. A conditional that omits a row and a permanent `VStack` containing conditional content do not have the same semantics: the latter still supplies a row when its child is absent. Applying this as a mechanical fix can leave blank rows, and a stack can change how multiple controls are laid out. The documented macOS toolbar observation supports investigating that hosting case; it does not establish that every conditional reusable view is defective. Narrow the rule to the demonstrated host problem, require preservation of visibility/layout semantics, and explicitly recommend filtering data when the intent is to omit list rows. Apple's [WWDC23 performance guidance](https://developer.apple.com/videos/play/wwdc2023/10160/) distinguishes filtering the collection from using a stack where appropriate and warns that row modifiers must move to the stack. The blank-row consequence is an inference from these row-count semantics, not a runtime reproduction performed in this review. The pre-existing unary-row rule at `performance.md:17` should receive the same omission caveat.

2. **Suggestion: give full-review records enough identity for freshness checks.** `plugins/baseline/skills/review/SKILL.md:21-26` makes the offer per package and relative to its latest release, but only specifies a journal title beginning "Full Review". Require package/path, review date, reviewed commit or release, and completed/partial coverage in the entry. In a repository with several packages, a title alone cannot establish which package was reviewed or whether the reviewed tree includes its latest release. The existing "Say when you cannot tell" fallback avoids a hard failure, but leaves the new freshness policy unnecessarily ambiguous. No other full-review recording contract exists in the plugin skills or journal.

3. **Suggestion: allow diagnostic observation before the exhaustive audit.** `plugins/baseline/skills/standards/SKILL.md:29-35` and `plugins/swift/skills/swiftui/SKILL.md:37-42` require reading every reference and auditing the failing path before experiments. Preserve the requirement to inspect dependencies and identity, but distinguish changing code speculatively from collecting the logs or minimal reproduction needed to locate the failing path. Topic-specific references such as localization, CloudKit and XCTest migration should remain conditional unless evidence makes them relevant. This is a workflow tradeoff, not a demonstrated runtime defect.
